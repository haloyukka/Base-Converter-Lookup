# システム要件定義書：基数変換＆早見表ツール (Base Converter & Lookup Web App)

## 1. システム概要・目的

Googleスプレッドシート「変換」シートに実装されていた「基数変換機能」および「早見表（参照テーブル）」をWeb技術（HTML5/CSS3/JavaScript）へ移行し、ブラウザ上で直感的・高速に動作するスタンドアロン静的Webアプリケーションとして提供する。

-----

## 2. システム構成・動作環境

  - **アーキテクチャ**: 静的フロントエンド（サーバーサイド処理なし、完全クライアントサイド実行）
  - **ファイル構成**:
      - `index.html`：UI構造およびマークアップ
      - `style.css`：スタイリング（レスポンシブデザイン、ダーク/ライトテーマ対応）
      - `script.js`：変換ロジック、動的テーブル生成、イベントハンドリング
  - **対応ブラウザ**: 主要モダンブラウザ（Google Chrome, Mozilla Firefox, Microsoft Edge, Safari の最新版）
  - **配備先想定**: GitHub Pages, 社内静的Webサーバー, またはローカル環境でのファイル参照

-----

## 3. 機能要件

### 3.1. 個別変換機能（双方向リアルタイム変換）

1.  **入力・連動仕様**
      - **DEC (10進数)**、**HEX (16進数)**、**BIN (2進数)** の3つの入力フィールドを配置。
      - いずれかのフィールドに値を入力すると、即座（`input` イベント）に残りの2つのフィールドに変換結果が反映される。
2.  **符号と数値表現**
      - 負の数に対応（2の補数表現を採用）。
      - ビット幅に応じた符号判定（例: 8bit/16bit/32bitなど、または指定有効桁数に基づく補数計算）。
3.  **有効桁数（ゼロ埋め / パディング）指定**
      - HEX用・BIN用にそれぞれ「有効桁数」の指定用入力欄を設置（デフォルト値例: HEX=2桁、BIN=8桁）。
      - 有効桁数が変更された場合、現在表示中の値のゼロ埋め桁数が即時再計算・更新される。
4.  **入力バリデーション（リアルタイム入力チェック）**
      - DEC：半角数字および符号（`-`）のみ許可。
      - HEX：`0-9`, `a-f`, `A-F`（大文字自動変換対応）および負値許容時の表現のみ許可。
      - BIN：`0`, `1` のみ許可。
      - 不正な文字が入力された場合、入力欄の枠線を赤色にし、ツールチップまたはフィールド下にエラーメッセージを表示。

### 3.2. 早見表（リファレンステーブル）動的生成機能

1.  **表示項目**
      - 列構成：`# (Index/Dec)`, `Dec2Hex (HEX)`, `Dec2Bin (BIN)`, `2^n`
2.  **動的範囲生成**
      - 「開始値（Start）」および「終了値（End）」の数値入力フィールドを配置。
      - 「表を生成」ボタンの押下（または入力確定）により、指定範囲のテーブル行を動的にDOM生成。
      - デフォルト初期表示：開始値 `0` 〜 終了値 `16`。
3.  **パディング連動**
      - 上段の有効桁数設定（HEX・BIN）をテーブル内の表記フォーマットにも反映。

### 3.3. ユーザビリティ・補助機能

1.  **ワンクリック・コピー機能**
      - 各入力欄（DEC, HEX, BIN）の横に「コピー」ボタンを配置。
      - クリック時に対象の文字列をクリップボードにコピーし、トースト通知（「コピーしました」）を表示。
2.  **テーブル・エクスポート機能**
      - 現在生成・表示されている早見表データを以下の形式で出力可能とする：
          - **CSV形式**: `.csv` ファイルとしてダウンロード
          - **Markdown形式**: クリップボードへコピー（GitHub README等へ貼り付け可能）
3.  **テーマ切替（ダークモード / ライトモード）**
      - 画面右上にテーマ切替スイッチ（トグルボタン）を配置。
      - OSの標準設定（`prefers-color-scheme`）の初期判定＋ローカルストレージ（`localStorage`）への設定保存。

## 5. 非機能要件

1.  **パフォーマンス**:
      - 早見表の生成は1,000行程度までブラウザがフリーズすることなく1秒未満で描画完了すること（過大入力に対する安全上限リミット（例: 最大1,000行まで）を設ける）。
2.  **保守性・可読性**:
      - 外部ライブラリ（jQuery, React等）に依存しない Vanilla JavaScript（ES6+）で実装し、長期間メンテナンスフリーで動作する構成とする。
3.  **アクセシビリティ**:
      - Tabキーによるフォーカス遷移、Enterキーでのフォーム送信/生成に対応。
